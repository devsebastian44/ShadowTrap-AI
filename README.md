# ShadowTrap-AI (Honeypot Intelligence Platform)

Welcome to ShadowTrap-AI, an intelligent SSH/Telnet honeypot platform designed to capture, classify, and analyze malicious login attempts and interactions in real-time.

## Ethical Focus & Professionalism
This project is built strictly for **defensive security research and education**.
All data captured is generated by unsolicited, unauthorized actors attempting to access the honeypot. It serves as a tool for threat intelligence gathering and helps cybersecurity professionals understand attacker methodologies, IP origins, and brute-force trends.

> **Warning:** Do not deploy this platform on production environments without understanding the risks of hosting a honeypot, as it intentionally invites attacks.

## Architecture
The platform is built on modern and scalable technologies:
- **Backend**: FastAPI (Python 3.10+) handling REST APIs and event processing.
- **Frontend**: Vanilla HTML/JS Dashboard via Nginx for lightweight, real-time metrics.
- **Database**: MongoDB for storing captured sessions, commands, and login attempts.
- **Honeypot Engine**: Cowrie (Containerized).
- **Deployment**: Docker & Docker Compose.

## Repository Structure & DevSecOps Flow

This repository is designed with a strict **Dual-Environment DevSecOps** philosophy.

### GitLab (Private Lab - Source of Truth)
The internal GitLab repository acts as the complete, private laboratory. It contains:
- Full CI/CD pipelines (`.gitlab-ci.yml`) for linting (Ruff) and security audits (`pip-audit`).
- Private configurations, testing modules, and the internal deployment scripts.

### GitHub (Public Portfolio)
This public GitHub repository is a **sanitized version** of the project. To prevent the leakage of sensitive testing data, honeypot credentials, or internal laboratory automation, the repository is filtered before release.

### `publish_public.ps1` (Automation)
The synchronization between the private lab (GitLab) and the public portfolio (GitHub) is governed by the `scripts/publish_public.ps1` script.

**Workflow:**
1. Development occurs on the `main` branch tracking GitLab (`origin-gitlab/main`).
2. Once CI passes, `publish_public.ps1` is executed locally.
3. The script verifies the state, pulls the latest changes from GitLab, and creates a transient `public` branch.
4. It forcefully removes private laboratory components (tests, configs, CI scripts) from the git index.
5. A sanitized commit is generated and pushed to GitHub's `main` branch.
6. The developer is safely returned to the pristine GitLab `main` branch.

This ensures the GitHub repository remains a clean, professional, and secure representation of the architecture without exposing the private infrastructure.
